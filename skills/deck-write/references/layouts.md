# layouts · 슬라이드 레이아웃

레이아웃은 `<!-- layout: 이름 -->` 으로 고른다. 생략하면 내용으로 추론한다(구성도 블록이면 diagram, 표면 table, `<!-- col -->` 이 있으면 two-col, 나머지는 message). 색·치수는 테마의 `pptx` 값에서 온다.

## 열 가지

| 이름 | 언제 | 본문 배치 |
|---|---|---|
| cover | 표지 | frontmatter 로 자동. 왼쪽 세로 띠, 제목·부제·조직·작성자·일자 |
| agenda | 목차 | `agenda: true` 로 자동. 슬라이드 제목 목록, 최대 여덟 개 |
| section | 장 구분 | 큰 번호와 섹션 제목 |
| message | 요점 전달 | 글머리표 본문(두 단계까지) |
| two-col | 좌우 비교·짝 | `<!-- col -->` 로 나눈다. 각 열 첫 줄이 `###` 이면 열 제목 |
| diagram | 구조·흐름 | 구성도 도형을 본문 영역에 맞춘다 |
| table | 정성 비교 | 표. 헤더는 강조색, 마지막 열은 판단 |
| timeline | 일정 | 좌측 항목, 우측 기간 막대 |
| chart | 수치 비교 | 네이티브 차트(발표 중 편집 가능) |
| image | 스크린샷·사진 | 그림 한 장과 캡션 |
| closing | 요청 사항 | 결정·예산·일정과 연락처 |

## two-col 예시

```markdown
# 도입 전후
<!-- layout: two-col -->
## 게이트웨이 도입으로 키 관리가 한곳으로 모인다
### 도입 전
- 팀별 키 12개
- 사용량 집계 불가
<!-- col -->
### 도입 후
- 키 한 벌
- 팀별 예산·사용량 자동 집계
```

## 고르는 법

- 흐름·구조를 설명할 때 글로 쓰지 말고 diagram 을 쓴다.
- 숫자로 크기를 비교할 때는 표 대신 chart 를 쓴다. 값의 크기가 눈에 보인다.
- 기능 유무·장단점처럼 크기가 아닌 비교는 표를 쓴다.
- 한 장에 담을 내용이 많으면 message 두 장으로 나눈다. 글자를 줄이지 않는다.
