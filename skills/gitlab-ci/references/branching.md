# branching · 브랜치 전략

## 권장: 트렁크 기반

- 기본 브랜치 하나에 자주 병합한다. 기능 브랜치는 짧게 유지한다.
- 릴리스는 태그로 찍는다. prod 배포는 태그에서만, 수동 승인으로.
- 미완성 기능은 기능 플래그로 감춘다. 오래 사는 브랜치를 만들지 않는다.

## MR 규칙

- MR 은 작게 유지한다. 리뷰어 한 명, 스쿼시 병합.
- 리팩토링과 기능 변경을 한 MR 에 섞지 않는다.
- 설명에 무엇을·왜와 관련 이슈를 적는다. 템플릿을 쓴다.

## gitflow 대안

릴리스 주기가 길고 여러 버전을 동시에 유지해야 하면 gitflow 를 쓴다. develop·release·hotfix 브랜치를 둔다. 대부분의 서비스에는 트렁크 기반이 더 단순하다.
