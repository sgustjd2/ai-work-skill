# checklist · 코드 리뷰 체크리스트

항목마다 ID 가 있다. 리뷰 결과에 근거로 ID 를 단다. 증상, 확인 방법, 전형적 수정을 함께 본다.

## 정확성 (C)

- C1 경계값: 0, 빈 값, None, 최대 길이에서 동작하는가.
- C2 예외 경로: 실패했을 때 자원을 정리하고 의미 있는 오류를 내는가.
- C3 동시성: 공유 상태에 경쟁이 없는가. 취소를 존중하는가.

## 비동기 (A)

- A1 이벤트 루프: 핸들러에서 블로킹 호출(`requests`, `time.sleep`, 동기 DB)이 없는가.
- A2 `asyncio.gather` 의 예외를 삼키지 않는가.
- A3 외부 호출에 타임아웃과 재시도가 있는가.

## FastAPI (F)

- F1 의존성 범위가 맞는가. 요청마다 새로 만들 것과 공유할 것을 구분했는가.
- F2 응답 모델과 상태 코드가 명시됐는가. 422 검증 오류를 처리하는가.
- F3 백그라운드 태스크가 요청 수명과 얽히지 않는가.

## LLM (L)

- L1 프롬프트 인젝션: 사용자 입력이 지시 자리에 들어가지 않는가.
- L2 출력 검증: 구조화 응답을 스키마로 확인하는가.
- L3 타임아웃·재시도·폴백이 있는가. 비용 상한이 있는가.
- L4 스트리밍 중간 오류를 처리하는가.
- L5 로그에 프롬프트·개인정보가 남지 않는가.

## 보안 (S)

- S1 시크릿이 코드·로그·응답에 없는가. 환경변수로 받는가.
- S2 경로 조작·SSRF·권한 확인.

## 데이터 (D)

- D1 트랜잭션 경계가 맞는가. N+1 쿼리가 없는가.
- D2 마이그레이션이 되돌릴 수 있는가.

## 테스트 (T)

- T1 이 변경에 대응하는 테스트가 있는가.
- T2 모킹 경계가 맞는가(외부만 모킹, 우리 로직은 실행).

## 구조 (X)

- X1 레이어 방향(api → services → infra)을 지키는가. 순환이 없는가.
- X2 중복이 늘지 않는가. 기존 함수를 재사용하는가.

## 운영 (O)

- O1 로그 수준이 맞는가. 메트릭·request_id 가 있는가.
- O2 설정 기본값이 안전한가.

## 리뷰가 증상만 고치지 않게

변경한 함수의 호출자를 먼저 찾는다. 한 호출 경로만 고치고 형제 경로를 놔두면 같은 버그가 남는다. 공유 함수에서 한 번 고치는 편이 낫다.
