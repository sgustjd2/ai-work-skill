# arch-doc-types · 아키텍처 문서 유형과 구성도 규약

아키텍처 문서를 쓸 때 읽는다. 유형별 뼈대와 구성도 작성 규칙을 담는다. 색·폰트·회사 사실은 여기 없다. `STYLE.md` 와 테마가 원본이다.

## 설계서

읽는 사람은 결재권자와 개발자 둘 다이다. 첫 화면에서 권고와 근거를 찾을 수 있어야 한다.

절 순서:

1. 개요. 무엇을 왜 하는지 세 줄에서 다섯 줄. 마지막 문장이 권고다.
2. 요구사항과 제약. 기능 요구와 비기능 요구, 지켜야 하는 제약을 나눈다.
3. 현행(AS-IS). 지금 구조와 한계를 구성도 하나와 함께 쓴다.
4. 목표(TO-BE). 바뀐 구조를 구성도로 보이고, 무엇이 달라지는지 잇는다.
5. 인터페이스. 서비스 사이의 계약을 표로. 메서드·경로·요청·응답·오류.
6. 데이터. 저장 대상과 보존 기간, 개인정보 취급.
7. 비기능. 성능·가용성·보안·비용을 목표치와 함께 표로.
8. 단계별 구축. 무엇을 어떤 순서로. 각 단계의 완료 조건.
9. 위험과 대응. 남은 위험 하나마다 완화책을 붙인다.
10. 추가 확인사항. `[확인 필요]` 로 표시한 항목을 모은다.

내용이 적은 절은 통합한다. 항상 남기는 절은 개요, 목표, 인터페이스, 단계별 구축이다.

## 구성도 3수준 (C4 참고)

한 장에 모든 상자를 그리지 않는다. 필요한 수준만 그린다.

1. 컨텍스트. 시스템 하나를 가운데 두고 사용자와 외부 시스템만. 경계가 무엇인지 보인다.
2. 컨테이너. 시스템 안의 실행 단위(웹, API, 게이트웨이, 데이터베이스, 큐). 대부분의 설계서는 이 수준이면 충분하다.
3. 컴포넌트. 한 컨테이너 안의 모듈. 리팩토링·상세 설계에서만 그린다.

## 인터페이스 정의서

엔드포인트를 표로 정리한다. 마지막 열은 설명이 아니라 판단이나 주의점을 쓴다.

| 메서드 | 경로 | 요청 | 응답 | 오류 | 설명 |
|---|---|---|---|---|---|

공통 절을 앞에 둔다. 인증 방식, 오류 형식(problem+json 등), 버전 규칙, 페이지네이션. `route_table.py --md` 의 표를 그대로 붙이고 손으로 다시 쓰지 않는다.

## 운영 런북

장애·운영 상황을 증상 기준으로 정리한다. 각 증상은 확인, 조치, 에스컬레이션 순서로 쓴다.

- 증상: 무엇이 보이는가 (알림 문구, 그래프 모양).
- 확인: 무엇을 먼저 보는가 (헬스체크, 로그, 대시보드).
- 조치: 순서대로 무엇을 하는가. 되돌리는 법도 함께.
- 에스컬레이션: 언제 누구에게 넘기는가.

## ADR (설계 결정 기록)

결정 하나에 한 파일. 짧게 쓴다.

- 제목과 상태(제안·채택·폐기·대체됨).
- 맥락. 왜 지금 결정하는가.
- 결정. 무엇으로 정했는가.
- 대안. 고려한 다른 선택과 왜 밀렸는가.
- 결과. 이 결정으로 생기는 좋은 점과 감수하는 점.

## 구성도 DSL 규약

구성도는 ` ```diagram ` 블록으로 쓴다. 그림을 문장으로 설명하지 않는다. 렌더러가 배치·색·화살표를 맡는다.

노드 종류는 여섯 가지다. 종류가 색 역할을 정하므로 임의 색을 넣지 않는다.

- `ui`: 사용자 화면(웹 포털, 관리 화면).
- `service`: 우리가 만드는 실행 단위(API 서버, 워커).
- `gateway`: 관문(LiteLLM, API 게이트웨이). 한 화면에 강조는 하나다.
- `data`: 저장소(PostgreSQL, Redis, 오브젝트 스토리지).
- `external`: 외부 제공자(Azure OpenAI, 결제사). 점선 테두리로 표시된다.
- `llm`: 모델 서빙(vLLM, 사내 GPU).

규칙:

- 화살표 라벨은 프로토콜이나 데이터를 쓴다. "HTTPS", "OpenAI 호환", "키·비용" 처럼. 동사를 남발하지 않는다.
- 그룹(`groups`)은 경계를 뜻한다. 플랫폼·제공자·사용자 채널처럼 묶는다. 신규 도입 영역은 `style: highlight` 로 표시한다.
- 요청 흐름은 왼쪽에서 오른쪽으로 둔다(`direction: LR`). 배포 다이어그램은 위에서 아래(`TB`)도 쓴다.
- 폴백·비동기 경로는 `style: dashed` 로 구분한다.
- 노드가 20개를 넘거나 그룹이 6개를 넘으면 렌더러가 경고한다. 그럴 때는 수준을 나눈다.
- 현행 구성이 `compose.yaml` 로 있으면 `diagram_from_compose` 로 초안을 만들고 손본다.
