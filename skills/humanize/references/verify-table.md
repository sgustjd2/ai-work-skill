# 확인 후보 표

그럴듯함과 사실 여부는 별개다. 문장이 자연스럽고 자신 있어 보일수록 먼저 근거를 찾는다. 위키독스 02-3(환각)을 이 저장소의 산출물에 맞게 옮겼다. 예시에 출처 형식 어구가 들어 있어 린터에서 제외한다.

## 문장을 두 종류로 가른다

1. 출처 없이도 일반 설명으로 볼 수 있는 문장. "게이트웨이는 요청을 한 곳에서 받아 모델로 넘긴다."
2. 출처·숫자·인용·고유명사·제도가 필요한 문장. 이것만 표에 넣는다.

## 종류 5가지

| 종류 | 예 | 잘 생기는 요청 | 근거가 되는 것 |
|---|---|---|---|
| 수치 | 62%, 3배, 12개 팀, 월 200만 원, 2026년 10월 | "숫자를 넣어 달라" | 견적서·측정 로그·사용자 자료. 반올림된 완벽한 숫자(100%, 10배)는 그 자체가 후보 |
| 출처 | "최근 조사에 따르면", "전문가들은", "OO 보고서에서는", "~로 알려져 있다", "~로 나타났다" | "연구를 바탕으로 설명해 달라" | 실제 문서 제목·URL·발행일. 형식만 있고 문서가 없으면 삭제 |
| 인용 | 따옴표 안의 발언, "~라고 밝혔다" | "인용문을 넣어 달라" | 원문 링크·회의록·메일. 없으면 인용부호를 빼고 사실/추론으로 |
| 고유명사 | 제품명·모델명·기관명·사람 이름·라틴 대문자 토큰 | "OO 에 대해 설명해 달라"(모르는 이름) | 공식 표기(용어집), 공식 문서. 이름 형태만 보고 붙인 설명은 삭제 |
| 제도 | 법률·규정·정책·지침·버전·가격 | 오래된 정보가 섞이는 주제 | 시행일·버전·확인일이 있는 공식 문서. 날짜를 같이 적는다 |

## 표 형식

```
| 줄 | 문장 | 종류 | 근거 | 상태 |
|---|---|---|---|---|
| 18 | 최근 조사에 따르면 도입 기업의 70%가 검증 기간을 절반으로 줄였다 | 출처·수치 | 없음 | 확인 필요 |
| 24 | LiteLLM v1.85 부터 요청 플래그가 프록시에서 무시된다 | 고유명사·제도 | https://docs.litellm.ai/docs/proxy/configs (2026-09-04 확인) | 확인됨 |
| 33 | 파일럿에서 폴백 응답 형식 오류가 2건 났다 | 수치 | 사용자 자료(파일럿 회고 메모) | 확인됨 |
| 41 | Azure 제공 시점은 10월로 예상된다 | 제도·수치 | 없음 | 추정 |
```

- 근거 열은 셋 중 하나만. 사용자 자료(파일·회의·메일 이름), URL(확인일 포함), `[확인 필요]`. 근거를 만들어 채우지 않는다.
- 상태는 확인됨·추정·확인 필요. 추정이면 본문 문장을 "~로 예상된다" 로 바꾼다(writing-rules-ko 의 사실/추론/권고 구분).
- 확인 필요는 본문에서도 `[확인 필요]` 마커를 달고 "추가 확인사항" 절에 모은다.
- 스크립트(`humanize_scan.py`)는 후보를 뽑을 뿐 근거를 모른다. 근거 열은 사람(모델)이 채운다.

## 환각이 잘 생기는 요청

| 요청 | 왜 위험한가 | 대신 |
|---|---|---|
| "최근 연구에 따르면" 식으로 출처를 넓게 요구 | 실제 자료가 없으면 연구 형식만 채운다 | 자료를 먼저 주거나, 자료가 없다고 쓴다 |
| 숫자·통계를 넣어 달라 | 근거 없는 자연스러운 수치가 나온다 | 측정치·견적서를 준다. 없으면 `[확인 필요]` |
| 인용문을 넣어 달라 | 누군가 말한 듯한 문장을 새로 만든다 | 원문을 붙여 넣는다 |
| 모르는 고유명사를 설명하게 함 | 이름 형태를 보고 그럴듯한 설명을 붙인다 | 공식 문서를 준다 |
| 오래된 정보가 섞인 주제 | 과거 정보와 현재 표현이 섞인다 | 버전·날짜를 명시하고 확인일을 적는다 |
| 완성된 글을 강하게 요구 | 빈칸을 남기기보다 매끄럽게 이어 간다 | `[확인 필요]` 를 남기고 계속 쓰는 것을 허용한다(H8) |

모델이 "확실합니다" 라고 말해도 그것은 답변 스타일이다. 사실 여부는 원자료와 공식 기준으로 확인한다.
