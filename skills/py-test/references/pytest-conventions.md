# pytest-conventions · pytest 규약

## 구성

- 테스트는 `tests/` 에 둔다. 파일은 `test_<대상>.py`, 함수는 `test_<동작>_<조건>_<기대>` 로 이름 짓는다.
- AAA 순서로 쓴다: 준비(Arrange), 실행(Act), 검증(Assert). 한 테스트는 한 가지를 확인한다.
- 마커: `deterministic`(어디서나), `live_llm`(실제 게이트웨이 호출, 기본 제외). `--strict-markers` 로 오타를 잡는다.

## 픽스처

- 범위를 좁게 잡는다. 함수 범위가 기본이다. 세션 범위는 재사용이 확실할 때만.
- 앱은 팩토리(`create_app`)로 매 테스트 새로 만든다. 전역 상태를 공유하지 않는다.
- 외부 경계(HTTP·DB)는 픽스처로 격리한다.
- 설정 캐시(`lru_cache`)는 테스트마다 비운다. 환경변수를 바꾼 테스트가 서로 새지 않게.

## 무엇을 먼저 테스트하나

우선순위는 서비스 로직, 그다음 API 계약, 그다음 인프라 어댑터다. 커버리지 숫자보다 분기와 오류 경로를 본다. services 층은 최소 80%를 목표로 한다.

## 파라미터화

같은 로직을 값만 바꿔 확인할 때는 `pytest.mark.parametrize` 를 쓴다. 케이스마다 함수를 복사하지 않는다. 경계값(0, 최대, 빈 값, None)을 포함한다.

## 하지 않는 것

- 테스트를 통과시키려고 검증을 약하게 만들기. 실패의 원인을 고친다.
- 실제 외부 서비스에 붙는 테스트를 기본 스위트에 두기. `live_llm` 으로 격리한다.
- 시간·난수·네트워크에 의존하는 테스트. 고정하거나 모킹한다.
