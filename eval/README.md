# eval · 골든 프롬프트와 결과 검증

목표: 스킬이 설치된 프로젝트에서 골든 프롬프트를 돌린 결과가 회사 표준을 지키는지 확인한다. 하드 룰 위반 0, 생성 문서의 테마 밖 색 0, 덱 소프트 룰 0.

## 골든 프롬프트

`prompts/01`~`08`. 각 파일은 붙여 넣을 프롬프트, 유도되는 슬롭, 기대 결과, 자동 검사를 담는다.

- 01 설계서(docx) · 02 덱(pptx) · 03 서비스 골격 · 04 MR 리뷰 · 05 게이트웨이 config · 06 트렌드 브리프 · 07 개발 가이드 · 08 리팩토링 계획

## 절차

1. 스킬이 설치된 테스트 프로젝트를 연다.
2. 프롬프트 하나를 새 세션에 붙여 넣고, 결과(`.doc.md`/`.deck.md` 원본과 렌더된 docx/pptx)를 `runs/<프롬프트>/` 에 저장한다.
3. 검증한다.

```
python eval/check_output.py runs/01-design-doc
```

## check_output 이 보는 것

- 산문 파일에 doc_lint 하드 룰(H1~H10) 0. 덱은 소프트 룰(S9~S12) 0.
- 생성 docx/pptx 의 색이 테마 팔레트와 그 파생 틴트 안에 있는가. 밖이면 FAIL.

문서·게이트웨이·서비스 검사는 각 스킬의 스크립트로 보강한다. config 는 `litellm-ops config-validate`, 서비스는 `uv run pytest`, 파이프라인은 `ci_lint.py`.

## 기준선

`results.md`. 도구가 만든 예시(설계서·덱 픽스처)를 렌더링해 check_output 이 PASS 하는지 확인한 결과다. 실제 골든 8개는 스킬을 붙인 세션에서 재현한다.
