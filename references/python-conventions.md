# python-conventions · 파이썬·FastAPI 규약

fastapi-service, py-review, py-test, py-refactor 가 공유하는 규약이다. 회사 사실은 여기 없다. 프로젝트의 `STYLE.md` 와 코드가 원본이다.

## 레이어

패키지를 세 층으로 나눈다. import 는 위에서 아래 한 방향으로만 흐른다.

- `api`: HTTP 경계. 요청·응답 스키마, 라우터, 의존성. 비즈니스 규칙을 두지 않는다.
- `services`: 도메인 로직. 외부 호출 조합, 프롬프트, 검증. 프레임워크에 묶이지 않는다.
- `infra`: 저장소·캐시·외부 어댑터. 상태를 두는 유일한 층.

`api` 는 `services` 와 `infra` 를 부를 수 있고, `services` 는 `infra` 를 부를 수 있다. 반대 방향 import 는 금지한다. `import_graph.py` 가 위반과 순환을 잡는다.

## 설정과 시크릿

- 설정은 환경변수로만 받는다. `pydantic-settings` 의 `Settings` 하나에 모은다. 코드에 기본 시크릿을 두지 않는다.
- 벤더 SDK 키를 앱에 두지 않는다. LLM 호출은 LiteLLM 게이트웨이를 거친다. 키는 게이트웨이가 갖는다.
- `.env` 는 git 에 올리지 않는다. `.env.example` 만 올린다.

## 비동기와 외부 호출

- 핸들러 안에서 블로킹 I/O 를 호출하지 않는다. `requests` 대신 `httpx.AsyncClient` 를 쓴다.
- 모든 외부 호출에 타임아웃을 건다. 재시도는 429 와 5xx 에만, 지수 백오프로 최대 2회.
- `asyncio.gather` 의 예외를 삼키지 않는다. 취소를 존중한다.

## 오류와 로깅

- 오류는 문제와 복구 방법을 함께 낸다. 사용자 응답은 RFC 9457 problem+json 으로 통일한다.
- 광범위한 `except Exception` 으로 끝내지 않는다. 잡았으면 로그를 남기고 다시 올리거나 명시적으로 처리한다.
- 로그는 JSON 으로, request_id 를 함께 남긴다. 프롬프트·응답 본문과 개인정보는 기본으로 남기지 않는다. 필요하면 DEBUG 에서만, 마스킹해서.

## 프롬프트

- 프롬프트는 코드에 인라인하지 않는다. `prompts/*.md` 파일에 두고 버전 필드를 붙인다.
- 프롬프트 변경은 코드처럼 리뷰 대상이다. 렌더 결과를 골든 파일로 고정한다.
- 사용자 입력은 프롬프트의 데이터 자리에만 넣는다. 지시 자리에 넣지 않는다.

## LLM 출력

- 구조화가 필요한 응답은 스키마로 검증한다. 실패하면 한 번 재요청하고, 그래도 실패하면 오류를 낸다.
- 비용 상한과 토큰 상한을 둔다. 스트리밍 응답의 중간 오류도 처리한다.

## 타입·이름·의존성

- 공개 함수에 타입 힌트를 단다. 반환 타입을 생략하지 않는다.
- 이름은 동작을 담는다. `data`, `handle`, `process` 같은 모호한 이름을 피한다.
- 의존성은 `uv` 로 관리하고 `uv.lock` 을 커밋한다. 새 의존성은 대안을 확인한 뒤 추가한다.

## 금지

- 전역 가변 상태. 상태는 `infra` 나 앱 상태(`app.state`)에만.
- `print` 로 로그를 남기기. 로거를 쓴다.
- async 함수 안의 동기 `requests`·`time.sleep`.
- 프롬프트·시크릿을 코드에 인라인.
