# genai-patterns · 생성형 AI 서비스 설계 패턴

fastapi-service, doc-write, deck-write, py-review 가 참조한다. 서비스 유형별 설계와 함정을 담는다. 회사 사실은 여기 없다.

## RAG

문서를 검색해 근거로 답하는 패턴이다. 단계는 다음 순서다.

1. 수집: 문서를 청크로 나눈다. 청크 크기와 겹침을 정한다(예: 800자, 겹침 100자). 너무 크면 검색이 뭉개지고 너무 작으면 맥락이 끊긴다.
2. 임베딩: 게이트웨이의 `/embeddings` 를 부른다. 모델과 차원을 고정한다.
3. 저장: pgvector 에 청크와 임베딩을 넣는다. 문서 출처를 함께 저장한다.
4. 검색: 질의를 임베딩해 상위 k 개를 찾는다. 유사도 임계와 k 를 설정값으로 둔다.
5. 조립: 검색 결과를 프롬프트에 넣고 출처 표기 형식을 지정한다.
6. 검증: 답에 근거 출처가 있는지 확인한다. 근거가 없으면 모른다고 답하게 한다.

하이브리드 검색(키워드 + 벡터)은 정확한 명칭·코드가 중요할 때 더한다. 순수 벡터 검색이 약한 곳이다.

## 구조화 출력과 툴 호출

- 응답을 코드로 다뤄야 하면 자유 텍스트 대신 스키마(JSON)를 요구한다. 게이트웨이의 구조화 출력 기능을 쓴다.
- 스키마 검증이 실패하면 오류 메시지를 넣어 한 번 재요청한다. 두 번째도 실패하면 사용자에게 오류를 낸다.
- 툴 호출은 도구 목록과 인자 스키마를 명확히 준다. 모델이 부른 인자를 실행 전에 검증한다.

## 에이전트

- 단순한 루프에서 시작한다. 단계 수 상한과 비용 상한을 둔다. 무한 루프를 막는다.
- 각 단계의 입력·출력·비용을 로그로 남긴다. 재현할 수 있어야 디버깅이 된다.
- 도구를 늘리기 전에 프롬프트로 풀리는지 본다. 도구가 많을수록 실패 지점이 는다.
- 사람이 확인해야 하는 행동(결제, 삭제, 외부 발송)은 자동 실행하지 않고 승인을 받는다.

## 비동기 작업

- 오래 걸리는 작업은 요청을 막지 않는다. `POST` 는 202 와 작업 id 를 주고, `GET /jobs/{id}` 로 상태를 조회한다.
- 같은 요청을 두 번 받아도 한 번만 실행되게 멱등 키를 받는다.
- 인프로세스 큐는 단일 프로세스에서만 안전하다. 워커가 여럿이면 Redis 큐로 옮긴다.

## 가드레일

- 입력: 길이 제한, 프롬프트 인젝션 패턴 확인. 사용자 입력을 지시 자리에 넣지 않는다.
- 출력: 개인정보·시크릿이 새지 않는지 확인한다. 필요하면 마스킹한다.
- 게이트웨이의 guardrails 와 앱의 검증은 역할을 나눈다. 게이트웨이는 공통 정책, 앱은 도메인 규칙.
- 거부·실패를 로그로 남겨 어떤 입력이 막혔는지 추적한다.
- 정책을 바꿀 때는 기존 골든 셋으로 회귀를 확인한다.

## 평가

- 골든 셋을 만든다. 20~50개의 질문과 기대 답으로 시작한다.
- 검색은 적중률로, 생성은 정답 포함률로 본다. 애매한 품질은 사람이 표본으로 확인한다.
- 대규모 평가는 promptfoo 같은 외부 도구로 돌린다. 이 저장소는 골든 파일·계약 테스트까지만 다룬다.

## 비용과 지연

- 모델을 등급으로 나눈다. 쉬운 작업은 작은 모델, 어려운 작업만 큰 모델.
- 같은 입력이 반복되면 캐시한다. 게이트웨이 캐시를 켠다.
- 사용자 체감이 중요하면 스트리밍을 먼저 고려한다. 첫 토큰까지의 시간을 줄인다.

## 설계서에 넣을 구성도

RAG 서비스의 목표 구성은 다음 형태다. 설계서에서는 ` ```diagram ` 블록으로 그린다.

```diagram
type: architecture
direction: LR
groups:
  - { id: app, label: 서비스, style: highlight }
nodes:
  - { id: api, label: RAG API, kind: service, group: app }
  - { id: gw, label: LiteLLM, kind: gateway, group: app }
  - { id: pg, label: pgvector, kind: data, group: app }
edges:
  - { from: api, to: gw, label: 임베딩·생성 }
  - { from: api, to: pg, label: 검색 }
```
